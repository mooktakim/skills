- CI is now opt-in per project (user agreed): setup recommends it only when people other than Claude change the code often, since Claude runs the lint locally.
- New composite action project-memory/action.yml: a project adds `- uses: mooktakim/skills/project-memory@<full commit SHA>`. It builds the command from its own downloaded source (`cargo install --path $GITHUB_ACTION_PATH`), caches it with actions/cache@v6 keyed by OS, arch and a hash of Cargo.toml, Cargo.lock and src/*.rs, then runs lint; input `directory` for monorepos. Upgrading a project = moving the pin (upgrade step 3).
- Rejected on the way: committing binaries into projects (one per platform, git bloat, unreviewable); a single cross-platform binary does not exist in a robust form (macOS universal covers macOS only; Cosmopolitan Rust is experimental). Release binaries stay an option if many projects use CI.
- This repo's macOS CI job runs the lint through `uses: ./project-memory`, so the action is exercised on every push. Test runs the action's shell steps locally (key, build on cache miss, lint). Protocol 0.4.0 (lint heading says CI is opt-in); this repo's docs/MEMORY.md upgraded.
