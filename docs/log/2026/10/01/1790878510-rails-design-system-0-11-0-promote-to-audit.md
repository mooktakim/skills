# rails-design-system 0.11.0: promote recurring review findings into the audit

- User decision: keep bin/audit_design (deterministic, 0 tokens, runs in hooks/CI/without Claude) and the design-reviewer (judgment) as layers; do not replace the script with the agent. New loop: agent finds new kinds of drift, the script then stops them for free.
- `docs/design-system/audit-rules`: project rules, one per line `<label> :: <ERE>`, # comments, leading spaces ok. Data file (like vendor-paths) so the script stays identical across apps (nudge compares it). Rules apply in --hook, --stop (added lines only, tagged `[rule: label]`) and full scan (`== rule: <label>: N`, which the nudge's sum already counts). design-ok exempts. Invalid regex / missing separator: warning on stderr, rule skipped.
- Refactor: `added_lines` split out of `added_findings`. Bash 3.2-safe (index loops, no "${arr[@]}" on possibly-empty arrays under set -u). Block message no longer always says "token utilities only"; explains untagged vs tagged lines.
- Agent report gains "Promote to the audit": proposed rule lines, each grep-tested over the section, reporting all hits; rules that hit legitimate code are not ready. Maintenance "Promotion" includes these; root block tells daily work to propose a rule when a finding recurs. Phase 3 documents the file but does not create it on a first run.
- Tested with /bin/bash 3.2.57 and Homebrew bash 5.3: no-rules behaviour unchanged, tagged hook/stop blocks, design-ok, broken rules skipped, full-scan counts, Phase 3 smoke test still passes; full-scan output byte-identical on dinehere/yardnote/maynard without a rules file.
