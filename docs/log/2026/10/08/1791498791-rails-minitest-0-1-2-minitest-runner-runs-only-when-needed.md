# rails-minitest 0.1.2: minitest-runner runs only when needed

- User asked whether anything stops minitest-runner from running when it is not needed. Gaps found: the agent description said "whenever a suite or subset needs running" (no more-than-one-file threshold, unlike the hook and SKILL.md); nothing said when no run is needed; nothing stopped double runs or asked the caller to pass a scope. Each delegation costs ~4-5k tokens of preloaded skill before the first command.
- Changes: agent description now "when a Minitest run covers more than one test file", with "Do not use for a single test file, or when nothing the tests exercise changed since the last green run", and "Pass it the exact files or path:line". Agent body: run exactly the caller's scope, widen only when a failure points outside it and say so; never repeat a run that passed unless code changed. SKILL.md and the SessionStart hook say the same (single test file runs directly; skip runs after docs/comments/CI-or-editor-only changes).
- Wording trap avoided: "config-only changes" was wrong for Rails (config/ routes and initializers change test results); the text says files the app never loads, and "config/ changes do count".
- Hook test asserts the threshold, the single-file rule, and the skip rule. 113 green on Ruby 4.0 and /usr/bin/ruby 2.6 + bash 3.2. Real delegation counts still pending (check from about 2026-10-22).
