# rails-minitest 0.1.0: Minitest standard, audit, and the tester agent

- Origin: user asked for research on the best Rails Minitest standards (unit tests for coverage and speed, shared code, shortcuts to a known state such as users with roles, anything else), then chose: a new plugin `rails-minitest` holding both a skill and the tester agent, `rails-tester` removed from rails-specialists, Minitest only (no RSpec), "done the best way possible".
- Sources: Rails guides and Rails source (tags 7.1.0-8.1.4 and main), 37signals' Fizzy test suite (fixtures only, `test/test_helpers/*_test_helper.rb`, 271 files), the 8.1 auth generator's SessionTestHelper, SimpleCov 1.3 source and docs, test-prof 1.6 docs, minitest History.
- Plugin: lean SKILL.md (detect, 14 rules, writing mode vs approval-gated suite mode) + references (test-kinds, fixtures, shortcuts, organisation, speed, coverage, flaky); `scripts/audit_tests` (Ruby 2.6+, run from the skill dir, not copied into apps): stack, setup, tests per kind, untested files (capped at 10 per dir, `--all`), 18 rules, record hot spots; `agents/rails-tester.md` preloads the skill via `skills: [rails-minitest:rails-minitest]`; SessionStart hook only in Rails apps with test/test_helper.rb and no rspec-rails.
- Key facts that differ from common advice: SimpleCov >= 1.0.1 with `start "rails"` merges parallelize workers itself (manual parallelize hooks are a 0.22 workaround and break the report on Rails 8.1.4 before SimpleCov 1.3.2); `work_stealing:` is Rails main only, not 8.1; Rails 8.1 scaffolds no system tests; Minitest 6 needs minitest-mock for `stub`, rejects assert_equal/assert_same nil, and makes plugins opt-in; WebMock.allow_net_connect! has no safe form; test-prof before_all must be included in ActiveSupport::TestCase before `parallelize` (workers:/with: only) or parallel workers leak data; model broadcasts are `_later` jobs, so assert_turbo_stream_broadcasts needs perform_enqueued_jobs.
- Verification: audit run on Fizzy (0.4 s, system Ruby 2.6); tightened skip/env-write/form-login rules after three false leads there; one rule broken on purpose to prove the tests fail. Headless `claude -p --plugin-dir` run in a fake Minitest app proved the hook fires, the skill is listed, the agent quotes rule 9 from the preloaded skill, and `${CLAUDE_SKILL_DIR}` is expanded in the preload. A fresh fact-check agent found 10 errors (before_all + parallel, broadcasts, 8.1-only session helper, WebMock, SimpleCov 1.2+ features, has_selector reasoning, fixture date equality, UUID ids, Current reset mechanism, 7.2-only assertions) plus gaps (jobs in system tests, after_commit/non-transactional tests, multiple databases, FK check for fixtures); all fixed after checking the key ones in source.
- rails-specialists 0.4.0: nine agents; delegation hook no longer names a tester; rails-model/jobs/debugger point at rails-minitest:rails-tester; README says where the tester went.
- Tests: test/audit_tests_test.rb (14) + hook tests; 113 green on Ruby 4.0 and on /usr/bin/ruby 2.6 + bash 3.2; plugin validate passes.
- Open: the skill defaults to fixtures, but the user's config_files rails.md tech defaults list factory_bot_rails for new apps - asked the user.
