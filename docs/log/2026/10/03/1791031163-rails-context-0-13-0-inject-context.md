# rails-context 0.13.0: hand directory context to shell work

- Problem: nested CLAUDE.md loads only on Read; Bash reads/edits, Grep, and Write of a new file bypass it. User considered per-file header comments pointing at ../AGENTS.md instead; I advised against (a pointer still needs model compliance, partial shell reads skip line 1, new files have none, Claude Code does not auto-load AGENTS.md, drift across every file). User chose a hook.
- `hooks/inject-context.sh` (bash wrapper, cached Ruby like rails-design-system's enforce.sh) -> `scripts/inject_context` (Ruby 2.6+, run from the plugin, not copied into apps). PostToolUse matcher `Bash|Write|Edit|Grep`; returns `hookSpecificOutput.additionalContext` (verified in code.claude.com/docs/en/hooks for PostToolUse and PreToolUse; chose Post - Pre fires after the model already chose the command anyway).
- Paths: Write/Edit file_path, Grep path, Bash words split on shell punctuation/`=`/`:`/globs; a word counts if it exists, or has a slash and an existing parent (new file). Resolved against input `cwd`. Only app/ lib/ test/ spec/ (same as context_report). Injects the CLAUDE.md chain up to, not incl., root; outermost first.
- Dedupe via the reach log: load/read/inject events for the session since its last start/compact. New log-context.sh mode `compact` (SessionStart matcher compact). A context file read via shell (`cat app/x/AGENTS.md`) is logged as read, not injected. Injections logged as `inject`; context_report shows them as "hook" reach.
- Root block wording kept: the hook fires after the call, so "read before changing" still matters.
- Tests: 5 new in hooks_test.rb. Note: TEST_RUBY does not reach hook-run scripts (the wrapper resolves the project's Ruby); checked inject_context on /usr/bin/ruby 2.6 by hand.
