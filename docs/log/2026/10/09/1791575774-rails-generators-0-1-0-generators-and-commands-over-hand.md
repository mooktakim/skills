# rails-generators 0.1.0: generators and commands over hand-written files

- Origin: user saw Claude write Rails migrations directly instead of using generators; asked for deep research on migrations and a skill so Claude uses the framework's commands instead of editing files. Evidence: maynard 21/35 and miraj 8/12 migrations have round hand-picked timestamps (blogger 0/28).
- Research: 2 agents against rails/rails source (8.0, 8.1.4 current, main = 8.2.alpha) and a fresh 8.1.4 app with every generator run under --pretend. Key facts: next_migration_number = max(now, highest+1); hand timestamps raise Duplicate/InvalidMigrationTimestampError (validate_migration_timestamps from load_defaults 7.2) or run out of order; older Migration[x.y] silently enables compatibility shims; `!` not-null field modifier is 8.0+; schema.rb columns sorted alphabetically 8.1.0-8.1.3, reverted 8.1.4; generators with no tty answer the overwrite prompt Y (always --skip); name clashes exit 0; credentials:edit takes VISUAL split without a shell (Ruby YAML one-liner works), invalid YAML still saves and breaks boot; stimulus generator runs manifest:update only without importmap; view_component generator is view_component:component.
- Plugin: SKILL.md (detect, 13 rules) + references migrations.md, generators.md, commands.md. No agent (rails-specialists:rails-model already owns migrations; it now generates and loads this skill) and no audit script (old hand-written migrations cannot be renamed once run).
- Guard: PreToolUse on Write|Edit|MultiEdit|Bash, bash prefilter then scripts/guard_files (Ruby 2.6+). Denies a new migration file (Write or shell redirect/tee/touch/cp/mv), any write to schema dumps, *.enc under config/, Gemfile.lock, in a dir with bin/rails; names the command, with --database for db/<name>_migrate. Editing an already-run migration (schema.rb version or structure.sql) gets an additionalContext note.
- rails-specialists 0.5.1: rails-model creates migrations with the generator.
- Verified: 140 tests green on current Ruby and /usr/bin/ruby 2.6 + bash 3.2; plugin validate. Headless claude -p in a Rails 8.1.4 app: a plain schema request loaded the skill unprompted and ran `generate migration AddPublishedAtAndSlugToPosts published_at:datetime:index slug:string!:uniq`, migrate, redo, schema diff; an order to Write a migration by hand under bypassPermissions was refused by the guard and Claude did not route around it.
