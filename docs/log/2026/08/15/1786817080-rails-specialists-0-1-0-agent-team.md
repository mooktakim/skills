# rails-specialists 0.1.0: Rails specialist agent team

- New plugin `rails-specialists` - first agent-shipping plugin in this repo (no SKILL.md; ships `agents/*.md` per the Claude Code plugin spec). 10 agents: rails-model, rails-hotwire, rails-tester, rails-jobs, rails-debugger, rails-reviewer, rails-security, rails-performance, rails-deploy, rails-upgrade. Each ~60-90 lines: role → detect-stack-first → domain checklists → boundaries → report format.
- Key decisions (user chose in planning Q&A): full ~10-agent roster over lean/minimal; NO model pinning (all agents inherit session model, no `model:` frontmatter); stack-agnostic (agents detect Gemfile/config and follow the project, no personal tech defaults baked in - user overrode the "encode rails.md defaults" recommendation).
- Doctrine carried over from rails-design-system 0.3.0: no architect/orchestrator agent - orchestration, conversation, approvals stay in the main session; agents never ask the user anything. Advisor agents (debugger, reviewer, security, performance) are read-only via `disallowedTools: Write, Edit, NotebookEdit`.
- Research basis: obie/claude-on-rails (7-agent team), ThibautBaissac/rails_ai_agents (19 agents, WHEN/WHEN-NOT descriptions), official plugins-reference spec (agents/ dir; hooks/mcpServers/permissionMode not allowed in plugin agents; namespaced `rails-specialists:<name>`). Anti-pattern avoided: one giant generalist agent (VoltAgent rails-expert, 358 lines).
- CLAUDE.md repo-structure section updated: plugins may ship SKILL.md and/or agents/; documented agent frontmatter rules. Marketplace + root README rows added. `claude plugin validate` passes for both.
- Not yet done: smoke-test in a real Rails app (install locally, confirm typeahead shows 10 agents, delegation fires).
