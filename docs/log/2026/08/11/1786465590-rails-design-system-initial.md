# rails-design-system 0.1.0: initial release

- New skill: bootstraps and maintains a design-system context repository at `docs/design-system/` in a target Rails app, plus a browsable HTML style guide (`index.html` + per-section `tokens.html`/`components.html`/`patterns.html` linked to the app's compiled CSS, kept purge-safe via an `@source` directive).
- Follows the rails-context pattern: survey → approval gate → generate → wire maintenance (`bin/audit_design`) → review; re-runnable, every re-run is maintenance (drift review, gap-fill, promotion, spec-vs-realized drift, divergences ledger, preview sync).
- Key decisions: sections are fully independent islands (no shared folder of any kind - user's explicit choice over a global-shared option); three tiers tokens → components → patterns with one-way dependencies; role-named tokens with a token-utilities-only rule so drift is greppable; specs are pure HTML + Tailwind with view-layer adapters (ERB/ViewComponent/Phlex) applied per Gemfile; Tailwind v4 required, no v3 path; generated docs carry no YAML frontmatter.
- Bundled curated catalog: 24 components + 7 page patterns across 11 files, all colour expressed via the role-token vocabulary fixed in `catalog/README.md`; every interactive sample carries focus-visible and disabled treatments. Deferred to a later minor: marketing page patterns (hero, pricing, CTA, footer) and error pages - SKILL.md's fallback (derive specs from app markup) makes the partial catalog safe.
- Structure: `SKILL.md` (~200 lines), `references/` 7 generation guides (questions + fictional target-shape excerpt each), `adapters/` 3 view-layer guides with a worked button example each, `catalog/` as above.
